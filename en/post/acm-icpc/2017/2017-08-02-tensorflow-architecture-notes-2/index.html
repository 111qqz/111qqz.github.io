对于要添加原生tensorflow中没有定义的运算的需求，首先建议在python层面，能不能将需要的op用其他原生的op拼凑起来。

如果不能这样做，或者这样做逻辑很复杂，或者这样做效率比较低的时候，我们才考虑在cpp层面添加一个新的op

去实现你自定义的运算需要如下步骤：

  1. 在C++文件中注册该运算。包含参数个数，类型，返回值类型，运算名称等。大概就是C++头文件中函数的定义吧.同时在此处也要定义shape function
  2. 用C++实现该运算，运算的实现被称之为kernel，该实现与第一步中的注册对应，相同功能的op对于不同的输入输出类型，或者是架构（GPU,CPU)可能 有不同的实现.
  3. 创建一个python包装器（**可选**），该包装器使得可以在python层面用API对该运算进行调用。在运算注册阶段会生成默认的包装器
  4. 编写计算该运算梯度 的函数**（可选）**
  5. 测试你新添加的运算。为了方便一般在python层面进行测试，不过你想在C++层面测试也没什么问题。

 59class OpDefBuilder {
 60 public:
 61  // Constructs an OpDef with just the name field set.

 64  // Adds an attr to this OpDefBuilder (and returns *this). The spec has
 65  // format "<name>:<type>" or "<name>:<type>=<default>"
 66  // where <name> matches regexp [a-zA-Z][a-zA-Z0-9_]*
 67  // (by convention only using capital letters for attrs that can be inferred)
 68  // <type> can be:
 69  //   "string", "int", "float", "bool", "type", "shape", or "tensor"
 70  //   "numbertype", "realnumbertype", "quantizedtype", "{int32,int64}"
 71  //       (meaning "type" with a restriction on valid values)
 72  //   "{\"foo\", \"bar\n baz\"}", or "{'foo', 'bar\n baz'}"
 73  //       (meaning "string" with a restriction on valid values)
 74  //   "list(string)", ..., "list(tensor)", "list(numbertype)", ...
 75  //       (meaning lists of the above types)
 76  //   "int >= 2" (meaning "int" with a restriction on valid values)
 77  //   "list(string) >= 2", "list(int) >= 2"
 78  //       (meaning "list(string)" / "list(int)" with length at least 2)

 84  //
 85  // TODO(josh11b): Perhaps support restrictions and defaults as optional
 86  // extra arguments to Attr() instead of encoding them in the spec string.
 87  // TODO(josh11b): Would like to have better dtype handling for tensor attrs:
 88  // * Ability to say the type of an input/output matches the type of

 90  // * Ability to restrict the type of the tensor like the existing
 91  //   restrictions for type attrs.

 93  OpDefBuilder& Attr(StringPiece spec);

 95  // Adds an input or output to this OpDefBuilder (and returns *this).
 96  // The spec has form "<name>:<type-expr>" or "<name>:Ref(<type-expr>)"
 97  // where <name> matches regexp [a-z][a-z0-9_]* and <type-expr> can be:
 98  // * For a single tensor: <type>
 99  // * For a sequence of tensors with the same type: <number>*<type>
100  // * For a sequence of tensors with different types: <type-list>

Implement the kernel for the op
#

 1#include "tensorflow/core/framework/op_kernel.h"
 2
 3using namespace tensorflow;
 4
 5class ZeroOutOp : public OpKernel {
 6 public:
 7  explicit ZeroOutOp(OpKernelConstruction* context) : OpKernel(context) {}
 8
 9  void Compute(OpKernelContext* context) override {
10    // Grab the input tensor
11    const Tensor& input_tensor = context->input(0);
12    auto input = input_tensor.flat<int32>();
13
14    // Create an output tensor
15    Tensor* output_tensor = NULL;
16    OP_REQUIRES_OK(context, context->allocate_output(0, input_tensor.shape(),
17                                                     &output_tensor));
18    auto output_flat = output_tensor->flat<int32>();
19
20    // Set all but the first element of the output tensor to 0.
21    const int N = input.size();
22    for (int i = 1; i < N; i++) {
23      output_flat(i) = 0;
24    }
25
26    // Preserve the first input value if possible.
27    if (N > 0) output_flat(0) = input(0);
28  }
29};

需要注意的是，你定义的运算的kernel可能被并行地访问，所以要求Compute method 一定是线程安全的。

可以通过添加互斥锁(c++11?)或者完全就不要通过类成员来共享状态。

可以使用 ResourceMgr 来追踪运算的状态。
